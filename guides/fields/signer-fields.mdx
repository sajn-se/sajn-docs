---
title: "Fields that parties fill in"
description: "Add form inputs that a party fills in while signing, next to values you fill in yourself"
---

In this guide, you add a form to a document. Some inputs you fill in before sending, and others the party fills in while signing, such as an address or a start date.

A FORM field holds a grid of inputs, called subfields. A subfield with a `partyId` in its `fieldMeta` belongs to that party: it's empty when you send the document, and the party fills it in on the signing page. A subfield without a `partyId` is yours: you fill it in, and the party sees the value as read-only text.

## Before you begin

- Store your API key in the `SAJN_API_KEY` environment variable. To create a key, go to workspace settings in the sajn app, then **Utvecklare** (Developer) > **API-nycklar** (API keys).
- Have a `DRAFT` document with at least one `SIGNER` party, and the party's `id`. For more information, see [Create a document](/guides/documents/create-document).

## Add a form with party inputs

<Steps>
  <Step title="Create the FORM field">
    Send a `POST` request to `/api/v1/documents/DOCUMENT_ID/fields`. Each subfield has an `id` that's unique in the form, a `row` and `column` in the grid, and its own `fieldMeta`. The following form has two values you fill in and two inputs for the party:

    <CodeGroup>

    ```bash curl
    curl -X POST https://app.sajn.se/api/v1/documents/DOCUMENT_ID/fields \
      -H "Authorization: Bearer $SAJN_API_KEY" \
      -H "Sajn-Version: 2026-10" \
      -H "Content-Type: application/json" \
      -d '{
        "type": "FORM",
        "position": 1,
        "fieldMeta": {
          "type": "FORM",
          "columns": 2,
          "fields": [
            { "id": "company", "key": "company", "row": 0, "column": 0,
              "fieldMeta": { "type": "input", "label": "Company", "value": "Example AB" } },
            { "id": "role", "key": "role", "row": 0, "column": 1,
              "fieldMeta": { "type": "input", "label": "Role", "value": "Developer" } },
            { "id": "address", "key": "address", "row": 1, "column": 0,
              "fieldMeta": { "type": "input", "label": "Home address", "partyId": "PARTY_ID", "required": true } },
            { "id": "start-date", "key": "start-date", "row": 1, "column": 1,
              "fieldMeta": { "type": "datepicker", "label": "Preferred start date", "partyId": "PARTY_ID" } }
          ]
        }
      }'
    ```

    ```javascript Node.js
    const documentId = "DOCUMENT_ID";
    const partyId = "PARTY_ID";

    const response = await fetch(`https://app.sajn.se/api/v1/documents/${documentId}/fields`, {
      method: "POST",
      headers: {
        Authorization: `Bearer ${process.env.SAJN_API_KEY}`,
        "Sajn-Version": "2026-10",
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        type: "FORM",
        position: 1,
        fieldMeta: {
          type: "FORM",
          columns: 2,
          fields: [
            { id: "company", key: "company", row: 0, column: 0,
              fieldMeta: { type: "input", label: "Company", value: "Example AB" } },
            { id: "role", key: "role", row: 0, column: 1,
              fieldMeta: { type: "input", label: "Role", value: "Developer" } },
            { id: "address", key: "address", row: 1, column: 0,
              fieldMeta: { type: "input", label: "Home address", partyId, required: true } },
            { id: "start-date", key: "start-date", row: 1, column: 1,
              fieldMeta: { type: "datepicker", label: "Preferred start date", partyId } },
          ],
        },
      }),
    });
    const { fields } = await response.json();
    console.log(fields[0].id);
    ```

    ```python Python
    import os

    import requests

    document_id = "DOCUMENT_ID"
    party_id = "PARTY_ID"

    response = requests.post(
        f"https://app.sajn.se/api/v1/documents/{document_id}/fields",
        headers={
            "Authorization": f"Bearer {os.environ['SAJN_API_KEY']}",
            "Sajn-Version": "2026-10",
        },
        json={
            "type": "FORM",
            "position": 1,
            "fieldMeta": {
                "type": "FORM",
                "columns": 2,
                "fields": [
                    {"id": "company", "key": "company", "row": 0, "column": 0,
                     "fieldMeta": {"type": "input", "label": "Company", "value": "Example AB"}},
                    {"id": "role", "key": "role", "row": 0, "column": 1,
                     "fieldMeta": {"type": "input", "label": "Role", "value": "Developer"}},
                    {"id": "address", "key": "address", "row": 1, "column": 0,
                     "fieldMeta": {"type": "input", "label": "Home address",
                                   "partyId": party_id, "required": True}},
                    {"id": "start-date", "key": "start-date", "row": 1, "column": 1,
                     "fieldMeta": {"type": "datepicker", "label": "Preferred start date",
                                   "partyId": party_id}},
                ],
            },
        },
    )
    response.raise_for_status()
    print(response.json()["fields"][0]["id"])
    ```

    </CodeGroup>

    Replace the following:

    - `DOCUMENT_ID`: the ID of the draft document.
    - `PARTY_ID`: the `id` of the party who fills in the inputs.

    The response is `{ "fields": [...] }` with the created FORM field. `position` is the field's 0-based place among the document's content blocks.

    A subfield's `key` lets you fill it in later without knowing the field ID. Keys can contain lowercase letters, digits, hyphens, and underscores.
  </Step>

  <Step title="Change your values before sending">
    To change the values you fill in, use [Fill in values on a document](/api-reference/fill-in-values-on-a-document) with the subfield keys. It writes every value in one request:

    ```bash
    curl -X PATCH https://app.sajn.se/api/v1/documents/DOCUMENT_ID/field-values \
      -H "Authorization: Bearer $SAJN_API_KEY" \
      -H "Sajn-Version: 2026-10" \
      -H "Content-Type: application/json" \
      -d '{ "values": [ { "key": "role", "value": "Senior developer" } ] }'
    ```

    A value that the party fills in, such as `address`, is read-only through this endpoint: its result has `success: false`.
  </Step>

  <Step title="Send the document">
    Send the document as usual. On the signing page, the party sees `Company` and `Role` as text, and `Home address` and `Preferred start date` as inputs. The party can't sign until every `required` input is filled in.

    After signing, the values are on the document. Read them with `GET /api/v1/documents/DOCUMENT_ID/field-values`, where each value has `filledBy` set to `signer` and the `partyId` of the party who filled it in.
  </Step>
</Steps>

## Subfield types

Every subfield type takes `label`, `placeholder`, `description`, `partyId`, and `required`:

- `input`: a single-line text input. The value is in `value`.
- `text`: a text area. `rows` sets its height, from 2 to 20.
- `number`: a number input.
- `datepicker`: a date picker.
- `select`: a drop-down list. Set `options` to a list such as `[{ "value": "Engineering" }, { "value": "Sales" }]`, and optionally `defaultValue`.
- `radio`: one choice from `options`.
- `checkbox`: any number of choices from `options`. The selected values are in `values`.
- `attachment`: a file that the party uploads. `allowedTypes` takes `pdf` and `image`.

## Give each party their own inputs

When a document has several signing parties, set each subfield's `partyId` to the party who owns it. A party can only fill in their own inputs. Another party's inputs show as empty until that party fills them in. For the signing order, see [Multi-party signing](/guides/documents/multi-party-signing).

## Change who fills in a subfield

To move a subfield to another party, or back to yourself, update it by key. Pass the subfield's `fieldMeta`; sajn merges it into the existing subfield and keeps the other properties, such as `label`:

```bash
curl -X PATCH https://app.sajn.se/api/v1/documents/DOCUMENT_ID/fields/key:address \
  -H "Authorization: Bearer $SAJN_API_KEY" \
  -H "Sajn-Version: 2026-10" \
  -H "Content-Type: application/json" \
  -d '{ "fieldMeta": { "type": "input", "partyId": null, "value": "Storgatan 1, Stockholm" } }'
```

The response is the whole FORM field that holds the subfield. To update several subfields, send them in one request to `PATCH /api/v1/documents/DOCUMENT_ID/fields` with an `updates` array. Separate concurrent `key:` requests to the same form overwrite each other.

## Handle errors

- `400 VALIDATION_FAILED`: a subfield is invalid, for example without `row` or with an unknown `type`. Read `issues` for the path.
- `400 INVALID_STATE`: the document isn't a `DRAFT`. Fields can change only before sending.
- `404 NOT_FOUND` on a `key:` update: no subfield has the key.

For the error shape and every code, see [Errors](/api-fundamentals/errors).
