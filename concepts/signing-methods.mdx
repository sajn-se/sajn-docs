---
title: "Signing methods"
description: "What each signature method proves about the signer, and which one to choose"
---

A party's `requiredSignature` decides how they sign. The methods differ in what they prove: that someone intended to sign, or that a verified person signed. Whichever method you choose, sajn seals the completed PDF with a PAdES seal, so any change to the file after signing is detectable.

## Signature levels

The eIDAS regulation defines three levels of electronic signature. Each sajn method maps to one of them:

| Level | What it proves | sajn methods |
|-------|----------------|--------------|
| Simple electronic signature (SES) | The signer intended to sign | `CLICK_TO_SIGN`, `DRAWING` |
| Advanced electronic signature (AES) | A verified person signed, through their national eID | `SE_BANKID`, `DK_MITID`, `DK_MITID_ERHVERV`, `FI_FTN`, `NO_BANKID_BIOMETRIC`, `NO_BANKID_HIGH`, `NL_IDIN` |
| Qualified electronic signature (QES) | The highest level, equal to a handwritten signature in the EU | `NO_QES` |

For most everyday agreements, a simple signature is enough. Use an eID when you need proof of who signed.

## Methods

| Value | Method | Level | The signer needs |
|-------|--------|-------|------------------|
| `CLICK_TO_SIGN` | Click a button and confirm | SES | A browser |
| `DRAWING` | Draw a signature with a mouse, trackpad, or finger | SES | A browser |
| `SE_BANKID` | Swedish BankID | AES | Swedish BankID |
| `DK_MITID` | Danish MitID, personal | AES | MitID |
| `DK_MITID_ERHVERV` | Danish MitID Erhverv, on behalf of a company | AES | MitID Erhverv |
| `FI_FTN` | Finnish Trust Network: Finnish bank credentials or Mobile ID | AES | FTN credentials |
| `NO_BANKID_BIOMETRIC` | Norwegian BankID | AES | Norwegian BankID |
| `NO_BANKID_HIGH` | Norwegian BankID, high assurance | AES | Norwegian BankID |
| `NO_QES` | Norwegian BankID, qualified signature | QES | Norwegian BankID |
| `NL_IDIN` | Dutch iDIN, through the signer's bank | AES | A Dutch bank that supports iDIN |
| `MANUAL` | Signed on paper, outside sajn | None in sajn | Nothing. Used for documents imported into the archive. |

eID schemes are switched on market by market. A `requiredSignature` that your account can't use yet fails with `400 VALIDATION_FAILED`, and the issue's message is `This eID scheme is not yet available`.

## List the available methods

Build a signature-method picker from [`GET /helpers/signature-methods`](/api-reference/list-selectable-signature-methods) instead of a hard-coded list. It returns the methods you can offer, with display labels:

```json
{
  "data": [
    { "code": "SE_BANKID", "label": "BankID" },
    { "code": "DK_MITID", "label": "MitID" },
    { "code": "DRAWING", "label": "Drawn signature" },
    { "code": "CLICK_TO_SIGN", "label": "Click to sign" }
  ]
}
```

The list leaves out `MANUAL`, and `NONE`, which a party gets when its role doesn't sign. Both are still accepted on input.

## Set the method on a party

Set `requiredSignature` on each party when you add or update it. Parties on the same document can use different methods:

```json
{
  "parties": [
    {
      "name": "Alex Lindqvist",
      "email": "alex@example.com",
      "role": "SIGNER",
      "signingOrder": 1,
      "requiredSignature": "SE_BANKID"
    },
    {
      "name": "Mette Hansen",
      "email": "mette@example.com",
      "role": "SIGNER",
      "signingOrder": 2,
      "requiredSignature": "DK_MITID"
    }
  ]
}
```

If you leave out `requiredSignature`, the party gets your organization's default method.

## Check who signed

An eID verifies the signer's identity, but not that it's the person you intended. To check that, set the party's `nationalId`, such as a Swedish personnummer. sajn compares it with the identity the eID returns. Without a `nationalId`, sajn compares names.

To read the identity that each eID verified, call [`GET /documents/{id}/signatures`](/api-reference/get-verified-signer-identities). It needs the `READ_DOCUMENT` permission, and for OAuth tokens, the `signatures:read` scope.

## Verify before signing

A signature method controls how the party signs. To check the party's identity before the document even opens, set `twoStepVerification`, for example to `SE_BANKID_BEFORE_SIGNING` or `SMS_BEFORE_SIGNING`. You can combine the two: a click-to-sign document behind a BankID check gives you a verified identity with a fast signing step. For the values, see [Parties](/concepts/parties#verification-before-opening).

## Choose a method

<AccordionGroup>
  <Accordion title="The fastest signing">
    Use `CLICK_TO_SIGN`. It works in any browser, with no app or credentials.
  </Accordion>
  <Accordion title="A visible signature on the document">
    Use `DRAWING`. The signer draws a signature, which appears in the signed PDF.
  </Accordion>
  <Accordion title="Proof of who signed, in Sweden">
    Use `SE_BANKID`, and set the party's `nationalId`.
  </Accordion>
  <Accordion title="Proof of who signed, elsewhere in the Nordics or the Netherlands">
    Use the signer's national eID: `DK_MITID`, `FI_FTN`, `NO_BANKID_BIOMETRIC`, or `NL_IDIN`. For Norwegian agreements that need a qualified signature, use `NO_QES`.
  </Accordion>
  <Accordion title="A company signs, in Denmark">
    Use `DK_MITID_ERHVERV`. It verifies the company's identity, with its registration number.
  </Accordion>
  <Accordion title="Signers in other countries">
    Use `DRAWING` or `CLICK_TO_SIGN`. `SE_BANKID` works only for people with Swedish BankID.
  </Accordion>
  <Accordion title="The signer is in the room with you">
    Set the party's `deliveryMethod` to `IN_APP`. The party signs in person on your device.
  </Accordion>
</AccordionGroup>

## Swedish BankID codes

Swedish BankID is `SE_BANKID`, and its verification check is `SE_BANKID_BEFORE_SIGNING`. API version `2026-10` rejects the older codes `BANKID` and `BANKID_BEFORE_SIGNING`. In API version `2026-09`, the API returns `BANKID` and `BANKID_BEFORE_SIGNING`, and accepts both spellings on input.
