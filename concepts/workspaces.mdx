---
title: "Workspaces"
description: "Isolated areas of an organization, each with its own documents, contacts, members, and credentials"
---

A **workspace** is an isolated area inside an [organization](/concepts/organizations), such as a department, a team, or a client. Every document lives in exactly one workspace, and so do the templates, contacts, and settings it uses.

Every API request works in one workspace: the one that the API key or OAuth token is bound to. You never send a workspace ID.

## What belongs to a workspace

Each workspace has its own set of the following:

- Documents, folders, and document categories
- Templates and forms
- Contacts and companies
- Custom fields
- Webhook endpoints
- API keys
- Members, workspace roles, and document settings, such as the default expiration and allowed signing methods

A document in one workspace can't use a contact, template, or custom field from another workspace.

## Workspace properties

The following properties identify a workspace:

| Property | Description | Example |
|----------|-------------|---------|
| `id` | Unique ID | `cm4k2x9p00003abcd0000qrst` |
| `slug` | Short random code used in dashboard URLs | `k3x9p` |
| `name` | Display name | `Sales` |

## Workspaces in the API

An API key acts in the workspace it was created in. To check which one, call [`GET /me`](/api-reference/get-authenticated-user-+-workspace-context):

```bash
curl https://app.sajn.se/api/v1/me \
  -H "Authorization: Bearer $SAJN_API_KEY" \
  -H "Sajn-Version: 2026-10"
```

To list the workspaces the key's user is a member of, call [`GET /workspaces`](/api-reference/list-accessible-workspaces). The workspace the key is bound to has `isCurrent` set to `true`. To work in another workspace, use a key created in that workspace.

## Members and roles

Each member has one workspace role per workspace. The role decides what the member, and every API key the member creates, can do in the workspace. Every workspace has the built-in roles **Läsare**, **Medarbetare**, **Säljare**, **Godkännare**, and **Avdelningsansvarig**, and you can add custom roles.

You can manage members and roles through the API:

| Resource | Endpoints | Required permission |
|----------|-----------|---------------------|
| Members | [List](/api-reference/list-workspace-members), add, update the role of, and remove members | `MANAGE_WORKSPACE_MEMBERS` |
| Invitations | [List pending invitations](/api-reference/list-pending-workspace-invitations), resend, and revoke | `MANAGE_WORKSPACE_MEMBERS` |
| Roles | [List](/api-reference/list-workspace-roles), create, update, and delete roles | `MANAGE_WORKSPACE_ROLES` |
| Permissions | [List the permissions you can assign](/api-reference/list-assignable-workspace-permissions) | `MANAGE_WORKSPACE_ROLES` |

## Workspace limits

Your plan decides how many workspaces the organization can have. To read the quota and current usage, call [`GET /limits`](/api-reference/get-plan-limits-and-usage) and read `quota.workspaces` and `usage.workspaces`. An unlimited quota is returned as `null`.
