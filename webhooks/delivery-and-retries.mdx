---
title: "Delivery and retries"
description: "How sajn delivers webhooks, retries failed attempts, logs every attempt, and pauses endpoints that keep failing"
---

sajn records every event before it delivers it, then queues one delivery for each endpoint that subscribes to the event type. Deliveries usually leave within seconds of the event. If queueing fails, a background sweep picks the event up again within about a minute, so an event isn't lost because of a problem on the sajn side.

## Successful and failed attempts

An attempt succeeds when your endpoint returns a `2xx` status code within 30 seconds. Anything else fails:

| Response | Result | Retried |
|----------|--------|---------|
| `2xx` | Success. | No |
| `5xx`, `408 Request Timeout`, or `429 Too Many Requests` | Failure. | Yes |
| A network error: a timeout after 30 seconds, a refused connection, a DNS or TLS failure | Failure. | Yes |
| `3xx` | Failure. sajn doesn't follow redirects. | No |
| Any other `4xx` | Failure. sajn treats it as a misconfiguration that a retry won't fix. | No |

To move an endpoint, [update its URL](/webhooks/manage-endpoints#update-an-endpoint) instead of redirecting. sajn also checks the URL's address before each attempt; a host that has started to resolve to a private address fails as a network error.

## Retry schedule

sajn makes up to five attempts over about 2.3 hours:

| Attempt | Wait before the attempt | Time after the first attempt |
|---------|-------------------------|------------------------------|
| 1 | None | 0 |
| 2 | 10 seconds | About 10 seconds |
| 3 | 100 seconds | About 2 minutes |
| 4 | About 17 minutes | About 19 minutes |
| 5 | 2 hours | About 2 hours 19 minutes |

Every attempt carries the same envelope `id` and the same `X-Sajn-Delivery` value, so a receiver that [deduplicates on `id`](/webhooks/overview#how-delivery-behaves) processes the event once. Each attempt has its own `X-Sajn-Signature` timestamp. Each attempt also uses the endpoint's API version at the time of the attempt, so if you change `apiVersion` while a delivery is being retried, the next attempt has the new shape.

After the fifth attempt, the delivery is final. To send it again, [replay it](/webhooks/replay-and-reconcile#replay-a-delivery).

### Rate limit your deliveries

To slow sajn down, return `429 Too Many Requests` with a `Retry-After` header, in seconds or as an HTTP date. sajn holds back every delivery to that endpoint until that time, and then sends them. Without a valid `Retry-After` header, sajn waits 60 seconds. The `429` response uses up one attempt of that delivery; the deliveries that sajn holds back don't use up attempts.

### Errors on the sajn side

If a delivery can't run because of a problem on the sajn side, sajn reschedules it every 5 minutes for up to 24 hours. These reschedules don't use up attempts.

## Ordering

sajn doesn't deliver events in order. Deliveries run in parallel, and a retried delivery can arrive after an event that happened later. To decide which update is newest, compare the envelope's `createdAt`, or fetch the resource from the API when the order matters.

## Delivery log

sajn logs every attempt and keeps the log for 7 days. Read it in the dashboard under **Inställningar > Utvecklare > Loggar**, or through the API:

- [`GET /api/v1/webhooks/{id}/deliveries`](/api-reference/list-webhook-deliveries) lists an endpoint's attempts, newest first. Filter with `status` (`SUCCESS` or `FAILED`) and `event`.
- [`GET /api/v1/webhooks/{id}/deliveries/{deliveryId}`](/api-reference/get-a-single-webhook-delivery) returns one attempt with the request body and your endpoint's response.

Each entry has the following fields:

| Field | Description |
|-------|-------------|
| `id` | The log entry ID. Pass it as `deliveryId` to the delivery endpoints. It's not the `X-Sajn-Delivery` value. |
| `event` | The event type. |
| `status` | `SUCCESS` or `FAILED`. |
| `responseCode` | Your endpoint's status code, or `0` for a network error or for an event that arrived while the endpoint was paused. |
| `attempt` | The attempt number, 1 to 5. An event that arrived while the endpoint was paused has `0`. |
| `isFinalAttempt` | `true` when sajn won't retry this delivery. |
| `replayOfId` | For a replayed delivery, the log entry it replays. Otherwise `null`. |
| `requestBody` | The envelope that sajn sent. |
| `responseBody` | Your endpoint's response. sajn stores up to 64 KB; a response that isn't JSON is cut to its first 1,000 characters. |
| `createdAt` | When the attempt ran. |

Keep your responses short. sajn ignores the response body; it only stores it for the log.

## Automatic pausing

When an endpoint keeps failing, sajn pauses it and stops sending to it. An endpoint is paused when both of the following are true:

- Its last 5 or more deliveries failed in a row. A delivery counts once, after its last attempt, not once per attempt.
- The first failure in that streak was at least 72 hours ago.

The status code doesn't matter. A burst of failures never pauses an endpoint; only a streak that lasts longer than 72 hours does. One successful delivery ends the streak, so an endpoint that answers some events with `2xx` and fails others is never paused. Endpoints that an integration installed are never paused, because the integration manages its own endpoint.

While an endpoint is paused, sajn doesn't send it anything. Each new event appears in the delivery log as **Sparad under paus** (Saved during pause), with `attempt` set to `0`, and stays there for 7 days. In **Inställningar > Utvecklare > Webhooks**, the endpoint's status is **Automatiskt pausad** (Automatically paused), with the reason, such as `HTTP_500` or `NETWORK_ERROR`, and the time. sajn also [notifies you](/webhooks/manage-endpoints#failure-notifications).

### Reactivate a paused endpoint

Fix your endpoint first, then reactivate it in the dashboard. The API can't lift a pause, and neither `enabled` nor saving the edit form changes it.

1. Go to **Inställningar > Utvecklare > Webhooks**.
2. If the URL was wrong, select **Redigera** from the endpoint's row menu, correct **Webhook URL**, and click **Spara**.
3. In the endpoint's **Status** column, click **Testa och återaktivera** (Test and reactivate).

sajn resends the most recent failed delivery from the last 7 days. If your endpoint returns `2xx`, sajn reactivates the endpoint and resets its failure count. If it fails, the endpoint stays paused and the dashboard shows the status code. If there's no failed delivery to test with, select **Återaktivera utan test** (Reactivate without testing) from the row menu instead.

Reactivating doesn't resend the events that arrived during the pause. To deliver them, open each one in **Loggar** and click **Sänd om** (Resend), or replay them through the API. For both, see [Replay and reconcile events](/webhooks/replay-and-reconcile).
